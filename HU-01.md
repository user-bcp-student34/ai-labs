# HU-01: Confirmar el contrato de autenticación

## Origen

- **H-AUTH-01 (auth):** Contrato observado de login pendiente de contrastar con el contrato acordado.
  - Evidencia: `auth/src/main/java/com/bcp/workshop/auth/AuthResource.java:15,22-24,26-49`
  - Evidencia: `auth/src/test/java/com/bcp/workshop/auth/AuthResourceTest.java:12-21`

## Contexto

Como consumidor de autenticación, necesito un contrato acordado y probado para `POST /auth/login`, para conocer de forma fiable los estados y campos de respuesta. El comportamiento observado contempla 400 para una petición o campos vacíos, 401 cuando no se encuentran las credenciales y una respuesta exitosa con token, `expiresIn`, usuario y `debug`. La prueba existente cubre solo el caso exitoso y comprueba username y token; falta contrastar esos comportamientos con el contrato acordado.

## Ajustes necesarios

- Confirmar el contrato esperado de `POST /auth/login` con sus consumidores.
- Completar pruebas de caracterización del endpoint para los casos observados y los campos definidos por el contrato acordado.
- Ajustar la implementación solo si las pruebas muestran una diferencia respecto del contrato confirmado, preservando la ruta y el formato acordados.

## Criterios de aceptacion

- Una prueba HTTP verifica que una petición vacía o con campos requeridos vacíos recibe el estado definido en el contrato acordado; el comportamiento actualmente observado es 400.
- Una prueba HTTP verifica que credenciales no encontradas reciben el estado definido en el contrato acordado; el comportamiento actualmente observado es 401.
- Una prueba HTTP verifica que el login exitoso devuelve los campos definidos en el contrato acordado; el comportamiento actualmente observado incluye token, `expiresIn`, usuario y `debug`. La prueba no registra ni compara valores de tokens.
- La suite de pruebas de auth pasa y cubre los casos acordados para `POST /auth/login`.

## Evidencia esperada

- Contrato de `POST /auth/login` confirmado por los consumidores, con petición, estados y campos de respuesta.
- Pruebas automatizadas del endpoint para petición vacía/campos vacíos, credenciales no encontradas y autenticación exitosa.
- Resultado de la suite de auth que permita verificar que las pruebas pasan, sin registrar tokens, secretos ni credenciales.
